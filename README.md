# NaNa 판례 자료실

공식 출처와 재이용 조건을 확인한 판결문을 건별 HTML로 공개하는 정적 자료실.

- 공개 URL: https://nanalab.kr/case-law-portal/
- 배포 대상: GitHub Pages, main 브랜치 루트, `.nojekyll`.
- 전수 수집을 주장하지 않습니다. 실제 범위는 `publication.json`과 `sitemap.xml`.
- 대한민국 공식 공개본부터 순차 수록하며, 인도 대법원 공식 원문을 별도 검토 후 추가합니다.
- 사이트의 원문 범위, 비식별·권리 설명은 `/sources/`에 있습니다.

## 한 건씩 추가

1. 공식 공개 경로의 이용 조건과 접근 허가를 확인합니다. 인증·CAPTCHA·방화벽을 우회하지 않습니다. API의 테스트 OC를 운영 자격으로 사용하지 않습니다.
2. 원본 HTML과 출처·조회시각·원본 SHA-256을 저장소 밖에 보관합니다.
3. 전문의 모든 텍스트와 구조를 대조하고 공식 비실명 표기를 유지합니다. 판시사항·판결요지·민간 주석은 판결문 전문과 혼동하지 않습니다. 표·그림·수식·별첨이 있으면 재현 범위를 검토해야 합니다. 한국 HTML 수입기는 비텍스트 구조가 있는 문서를 거절합니다. 인도 공식 PDF는 모든 쪽의 텍스트와 고정폭 표 배치를 검증한 뒤 원래 줄바꿈을 보존해 수록하며, 스캔·이미지가 있는 자료는 별도 검토합니다. 현재 인도 원문의 QR 래스터는 공개 중립인용만 담고 있음을 확인하고 픽셀 보존·해시 검증 후 해당 쪽에 별도로 재현합니다. 이를 일괄 제외하는 정책이 아닙니다.
4. 메타데이터·권리·비실명·전문 완전성 검토를 모두 완료한 JSON만 `python scripts/import_reviewed.py /path/to/record.json`으로 한 건씩 추가합니다. 인접 원본 HTML의 해시를 다시 확인합니다. 동일 ID/출처/본문/법원·사건번호·선고일의 중복과 충돌을 거절합니다.
   신규 수입에는 `privacyReview.contextualReview`로 전문 읽기, 사적 성명·민감 사실·단서 결합, 직무상 성명과의 구별을 기록하고 구체적인 판단 근거를 남겨야 합니다. 공식 공개나 가림표만으로 승인하지 않습니다. `privacy_gate.py`의 패턴은 수동 심사 신호일 뿐이며, 신호가 없다고 자동 승인하지 않습니다. 미해결 우려가 있으면 수입하지 않습니다.
5. `python scripts/build.py --check`, `python scripts/validate.py`, `python -m unittest discover -s tests`, `node --check assets/app.js`를 실행합니다. 브라우저 검색·빈 결과·키보드·모바일·개별 페이지를 검사합니다.
6. 검증한 변경만 commit/push하고 해당 SHA의 Pages build 완료를 확인합니다. `python scripts/verify_public.py --report artifacts/live-release.json`으로 공개된 전체 본문·원문 이미지 해시·자산·국가별 목록·사이트맵·루트 연결을 로컬 검토본과 대조합니다. 이전 버전이 남아 있으면 성공으로 처리하지 않습니다. 이 검증기는 NaNa 공개 사이트만 읽으며 공식 출처를 추가 수집하지 않습니다.

검토된 묶음은 `python scripts/import_batch.py /path/to/manifest.json`으로 먼저 dry-run합니다. 1~50건의 모든 원본·이미지 해시, 승인 상태, 중복과 충돌을 선검사합니다. 확인 후 `--apply`를 붙이면 한 건씩 로컬에 반영합니다. 이 명령은 자료를 수집하거나 GitHub에 배포하지 않습니다. 이미 수록된 항목은 덮어쓰지 않으며, 정정 사항은 별도 검토합니다.

공개 검색에서 발견한 정확한 공식 URL은 `python scripts/check_candidate.py 'URL'`로 수집 전에 대조할 수 있습니다. 수록된 원문과 재검토가 필요한 원문을 구분하며 네트워크 요청을 하지 않습니다. `data/review-ledger.json`은 보류·일시 오류 원문의 URL 해시와 일반적인 검토 사유만 저장합니다. 해당 원문, URL, 당사자 이름은 넣지 않습니다. 보류를 자동 재시도하거나 검색 결과의 반복을 전체 판례 수집 완료로 해석하지 않습니다.

판례 경로는 `<국가코드>/cases/<stable-id>/index.html`입니다. 한국은 `kr/`, 인도는 `in/`을 사용합니다. 각 페이지에는 공식 출처·법원·사건번호·선고일·수집일·검토일·출처/본문 해시·추출 한계가 표시됩니다. 새로운 관할은 출처 정책과 검증 규칙을 추가한 후 수록할 수 있습니다. 이 저장소에는 자율 크롤러나 스케줄러가 포함되어 있지 않습니다. 수록 상한(45,000 URL) 도달 전에 목록·leaf sitemap을 분할하고 루트 사이트맵 등록도 함께 갱신해야 합니다.

## 생성과 검증

Python 표준 라이브러리만 필요합니다. `python scripts/build.py`가 목록, 상세, 메타데이터, 사이트맵을 재생성합니다. 원본 보존/텍스트 해시는 `data/cases/*.json`에 남습니다. 수입은 기존 판례를 덮어쓰지 않습니다. 정정·비공개 전환은 별도로 검토해야 합니다.

추가 비식별본은 `privacyEdits`의 변경 범위·원문과 공개본의 별도 해시·검토 시각을 기록하고 페이지와 목록에 표시합니다. 비식별 전 원문이나 실제 대체 대상 문자열을 새 공개 메타데이터에 넣지 않습니다. 공식 원문과 현재 공개본이 같다고 표시하지 않으며, 이전 복제본·버전 이력의 삭제나 완전한 익명화를 보증하지 않습니다. 기존 수록본의 과거 비실명 보존 표시는 새로운 맥락 심사와 같은 의미가 아닙니다.

기존 NaNa Lab 공통 GTM, GA4, AdSense 로더, Cloudflare 분석 및 책 배너를 적용합니다. 로더 존재 검사는 실제 분석 수신·광고 송출을 인증하지 않습니다. 인증값이나 API 키는 공개 저장소에 넣지 않습니다.
